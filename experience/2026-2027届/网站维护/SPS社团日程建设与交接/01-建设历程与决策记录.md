# SPS 社团日程建设历程与决策记录

最初要解决的问题很具体：每位社员都能安排有截止时间的工作，并让参与者勾选完成。后续工作逐渐覆盖活动筹备、部门协作、日历协调和经验交接。界面一直保留绿色视觉与紧凑工作台，但实现方式和操作流程根据实际使用不断调整。

## 从微信原型转向独立网页

2026 年 10 月 29 日，先做了中文微信小程序原型及本机预览，支持“逐人完成”和“协作完成”。当时没有 AppID，云端尚未接入；本机演示中的任务不能跨设备共享。随后研究了 CloudBase 的开通、资源点和刷新成本，并优化读取方式：自己的操作确认后立即更新，其他变化采用自适应增量同步，页面隐藏或断网时暂停。

用户后来明确选择 GitHub Pages 加 Cloudflare 后端，保留原有设计；登录采用“社团邀请码＋自设用户名和密码”，成员无需 GitHub 账号。项目独立成仓库，后来使用 SPS 组织的仓库与 Pages 地址，避免让社团站点依附于个人综合工作区。当前运行入口以本系列导航中的正式地址为准。

这次转向保留下来的经验是：领域规则、同步逻辑和展示层应能分开调整；演示通过、云端接通和正式部署是三个不同阶段。没有把原型数据直接当成生产数据。

## 域名接入与数据保留

10 月 29 日接入域名协作者提供的 API 域名。用户选择保留原来的账号与任务数据库，新增一个固定上游的 Worker 网关。正式路径是“Pages → 自定义 API 域名网关 → 原 API Worker → 原 Durable Object”。

这是一项入口调整，没有把数据库搬到另一个账号。详细操作已单列为[Cloudflare 工作流专题](https://sps-club-schedule.github.io/sps-club-schedule/#/experience?folder=2026-2027%E5%B1%8A%2F%E7%BD%91%E7%AB%99%E7%BB%B4%E6%8A%A4%2FSPS%E7%A4%BE%E5%9B%A2%E6%97%A5%E7%A8%8B%E5%BB%BA%E8%AE%BE%E4%B8%8E%E4%BA%A4%E6%8E%A5%2F%E7%BB%99%E6%88%90%E5%91%98%E7%9C%8B%E7%9A%84%E6%B5%81%E7%A8%8B&document=repo%3A2026-2027%E5%B1%8A%2F%E7%BD%91%E7%AB%99%E7%BB%B4%E6%8A%A4%2FSPS%E7%A4%BE%E5%9B%A2%E6%97%A5%E7%A8%8B%E5%BB%BA%E8%AE%BE%E4%B8%8E%E4%BA%A4%E6%8E%A5%2F%E7%BB%99%E6%88%90%E5%91%98%E7%9C%8B%E7%9A%84%E6%B5%81%E7%A8%8B%2F08-Cloudflare%E5%B7%A5%E4%BD%9C%E6%B5%81%E8%AE%B2%E8%A7%A3.md)。网关保留 CORS、会话与限流语义，遇到上游 HTML 错误时返回前端能识别的 JSON。部署时固定两个 Worker 所属账号，避免多账号授权后投错位置。

## 从待办扩展到活动筹备

10 月 30 日补齐截止日历、一级子任务、共享模板、部门分配和主任务持续时段。以研讨班为例，预约教室、宣传文案、海报、转发宣传及讲义准备分别分配给实际负责人。

| 变化 | 解决的问题 | 保留下来的规则 |
| --- | --- | --- |
| 独立子任务 | 一项活动包含多个人的不同工作 | 每步有自己的负责人、DDL、完成方式 |
| 部门选择 | 每次逐个选人太慢 | 模板保留部门规则，发布时解析最新成员 |
| 持续时段 | 活动发生时间不能只用 DDL 表达 | 主任务可有开始与结束；子任务只有 DDL |
| 模板默认时长 | 每次重复填写结束时间 | 开始时间加默认时长，手动修改后停止覆盖 |
| 归档恢复 | 误归档后需要保留历史地恢复 | 后台单独入口，保留原分工和完成记录 |

所有成员可以创建、编辑和分类共享模板。已发布任务是一次明确的安排，不随模板、部门名单变化而自动改写。

## 权限与电脑手机布局

成员管理陆续加入邀请码权限、自助改用户名与密码、管理员重设链接、账号删除和审计记录。随后区分部门管理与网页维护管理，再设置总管理员和创始人。公开成员页统一显示“管理员”；内部类型服务于后台能力分配，避免将职级展示给普通成员。

电脑布局最初讨论过移动窄面板，最终采用左侧导航、窄工作台与右侧宽编辑区；各区域独立滚动。手机直接进入编辑或大日历页面。这个调整说明：同一功能可以共享逻辑，但不同屏幕需要不同的信息摆放方式。

## 日历互通与一次漏显示修复

持续任务接入物院社团预约页面，自动带上活动名称、时段和地点；未填地点显示“未定”。日程页也读取预约页公开活动，排除课程；成员能导出自己的 ICS 文件。

第一次去重按“SPS 社团名”整体过滤，误伤手动创建的 SPS 活动。10 月 30 日改成识别日程生成的来源 ID，仅排除回流副本。另一个容易混淆的现象是：只有 DDL 的任务不会变成预约页时间块。这是同步范围设计，不能按漏同步处理。

## 经验档案与成员教程

经验档案明确选择公开可读、SPS 成员可投稿，同时支持网页存储和仓库投稿，两种来源显示在同一目录。之后加入 Markdown、LaTeX 公式与纯文本在线阅读、正文修改和另存副本。

成员教程最初是说明弹窗，随后按用户要求改成高亮真实控件的操作引导，又增加“上一步”和经验档案部分。教程需要保留草稿、避免重复添加子任务，也不能为了演示自动发布内容。

自动更新也采用同一原则：打开页面能加载新资源，正在编辑时则等待安全时机。内容哈希、版本清单和暂停刷新条件共同解决长期打开页面的问题。

## 11 月 4 日的模板进阶与新尝试

新增模板角色，让多个步骤共用一次人员选择；角色只是活动分工，不是账号权限。随后增加子任务依赖，明确“可见依赖不等于强制完成顺序”。

耗时倒排进一步利用依赖计算日期：文案 3 天、海报 1 天、宣传 1 天，宣传至少提前主任务 1 天完成，得到文案最晚前 6 天开始、前 3 天完成。多个下游约束取最早截止；独立分支可以并行。

同日的其他工作具有不同状态：

- Android 入口经历 1.0 会话保存、1.1 可选密码保存、1.2 普通登录默认记住密码；安装包本地交付并做模拟器测试。
- 邮件通知已选择 Resend，准备了给域名管理员及其 agent 的 DNS 交接材料；通知代码仍待接入。
- 部门管理员首次登录的模板专项教程随后已发布，包含 24 步高亮引导、云端完成状态与本地练习，网页和 App 共用。
- 新提出外部主讲人与非核心角色需求，仍在开发：受限账号只处理自己的分工；未注册者可按姓名分配，并记录由谁代为完成。
