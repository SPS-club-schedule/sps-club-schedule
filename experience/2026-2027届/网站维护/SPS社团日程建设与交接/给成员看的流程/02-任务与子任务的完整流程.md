# 任务与子任务的完整流程

任务表达“谁在什么时候之前完成什么”。活动本身可以再有发生时段；筹备分工则放在子任务里。

## 发布一项任务

1. 打开新任务，写清标题、交付物和必要说明。例如“整理研讨班讲义”，说明应包含提交位置与完成标准。
2. 选择完成方式与参与成员。“逐人完成”要求每位负责人记录自己的完成；“协作完成”由参与者完成整项工作。
3. 默认填写 DDL；只有确实存在活动时段时才启用“有持续时段”。
4. 核对负责人、北京时间和说明后发布。返回详情确认记录，负责人的“我的待办”会出现相应工作。

按部门选择会把名单切换为该部门全体成员，也可再手动调整。发布后的名单固定，后来加入部门的人不会自动承担旧任务。

## 区分 DDL 与活动时段

假设研讨班周日 14:00—16:00 举行，讲义周六 20:00 前准备完毕：研讨班主任务可以设置周日活动时段，讲义子任务设置周六 DDL。

主任务开启时段后，DDL 默认跟随开始时间；可以手动改为独立日期，之后调整时段不会覆盖它。“恢复跟随开始时间”可恢复自动跟随。关闭时段会保留当前 DDL。子任务没有持续时段。

## 拆分子任务

在主任务详情点击“＋ 添加子任务”，分别设置标题、负责人、DDL 和完成方式。当前只有一级子任务，适合把活动拆成可交付的几步，不适合无限嵌套。

主任务发布者与社团创建者可以管理分工。子任务有完成记录后，要先撤销相应完成记录，才能更换负责人。主任务与子任务各自标记完成，不能因为主任务结束就推定每项准备工作都完成了。

如果经常重复同一组分工，改用[共享模板](https://sps-club-schedule.github.io/sps-club-schedule/#/experience?folder=2026-2027%E5%B1%8A%2F%E7%BD%91%E7%AB%99%E7%BB%B4%E6%8A%A4%2FSPS%E7%A4%BE%E5%9B%A2%E6%97%A5%E7%A8%8B%E5%BB%BA%E8%AE%BE%E4%B8%8E%E4%BA%A4%E6%8E%A5%2F%E7%BB%99%E6%88%90%E5%91%98%E7%9C%8B%E7%9A%84%E6%B5%81%E7%A8%8B&document=repo%3A2026-2027%E5%B1%8A%2F%E7%BD%91%E7%AB%99%E7%BB%B4%E6%8A%A4%2FSPS%E7%A4%BE%E5%9B%A2%E6%97%A5%E7%A8%8B%E5%BB%BA%E8%AE%BE%E4%B8%8E%E4%BA%A4%E6%8E%A5%2F%E7%BB%99%E6%88%90%E5%91%98%E7%9C%8B%E7%9A%84%E6%B5%81%E7%A8%8B%2F03-%E6%A8%A1%E6%9D%BF%E8%A7%92%E8%89%B2%E4%BE%9D%E8%B5%96%E4%B8%8E%E8%80%97%E6%97%B6%E5%80%92%E6%8E%92.md)，保留步骤结构并在每次使用时选人和定日期。

## 完成 撤销 与归档

逐人任务只记录自己的完成；协作任务按其模式记录整项完成。误勾可以撤销。服务器确认后界面才将本次修改视为已保存；网络失败时先刷新核对结果，避免反复提交造成误解。

归档将内容从日常列表移走，保留历史。归档主任务会一并收起其未归档子任务。恢复由管理员在后台处理，保留原 DDL，逾期不会自动变成未来日期。

## 常见现象

| 现象 | 应先核对 |
| --- | --- |
| 我看不到同学的 DDL | 普通成员日历默认只显示自己的截止事项 |
| 部门换人后旧任务没变 | 发布时已确定名单，需要重新安排具体任务 |
| 完成主任务后仍有子任务 | 主子任务分别记录完成状态 |
| 海报可以先于文案标记完成 | 依赖关系不锁定完成按钮 |
| 活动没有出现在预约页 | 检查是否为正式 SPS 社团的未归档主任务，且同时有开始和结束时间 |
| 页面显示旧状态 | 先使用更新并检查网络；正在编辑时新版加载会暂缓 |
