# 数据规则与兼容约束

功能可以演进，已发布任务和账号关系必须保持明确。以下规则来自本次基线的领域、权限与存储代码，修改时应同时检查服务端及实际 SQLite 行为。

## 存储身份与原子写入

`ClubService`、绑定 `CLUB_SERVICE`、已有 migration 标签以及对象名 `sps-club-service-v1` 都关系到现有数据位置。不能把更改这些标识当成一般重构。

`records` 存业务记录，认证数据有独立账号、会话与版本等表。许多新能力通过既有 JSON 记录添加可选字段实现。业务对象修改与社团同步版本必须在同一事务中提交；多任务发布失败不能留下半组任务。

Durable Object 内还需要串行处理异步领域操作，不能只凭“单对象”就推断任意异步调用都不会交错。数据恢复、清库和变更存储归属属于独立操作，不是普通前端发布的附带步骤。

## 任务与人员

主任务可以只设 `dueAt`，也可以有 `startsAt`、`endsAt`、`deadlineFollowsStart`、地点。子任务只有 DDL。旧客户端省略时段字段时保留已有值，手动修改的 DDL 不应被后续自动计算覆盖。

任务发布时保存最终成员 ID。模板里的部门、跟随主任务和角色规则在服务端解析，发布后不随部门换人或模板改名漂移。已有完成记录的子任务更换人员有额外约束。归档保留完成记录；恢复主任务只带回同次随主任务归档的子任务。

任务内容管理主要由发布者、关联主任务发布者与创始人承担。账号管理员不因此自动获得全部任务的内容编辑权。模板共享编辑和模板归档也有不同规则，应分别读对应领域操作。

## 三类角色不要混淆

- 成员的管理类型决定后台授权。
- 成员所属部门决定部门范围与部门选人。
- 模板角色只是一次活动的人员分工。

模板定义 `roles: [{id,name}]`，步骤通过 `roleId` 绑定，最多 20 个角色。ID 应稳定，不能用展示名或数组位置做关系键。改名、排序、复制保留关系；删除角色时显式解除关联。角色分配与部门、跟随主任务等步骤规则不能同时产生矛盾。

## 依赖与倒排

模板步骤使用稳定 `id` 和 `dependsOn`。服务端校验 ID 唯一、引用同一模板、不自依赖且无环。发布时把步骤引用映射到本次新建的实际任务 ID，写入 `dependsOnTaskIds`，整组原子提交。

完成与撤销完成不依赖前置任务状态，这是明确的产品规则。依赖显示应容忍被归档的目标，给出“已归档或不可用”提示，恢复后可继续关联。

`schedulingMode` 为 `independent` 或 `backward`。倒排每步有 `estimateMinutes`、`anchorToMain`，并复用 `daysBefore`。令 A(i) 为本步最晚约束、d(i) 为耗时，j 是直接依赖 i 的后续任务：

```text
F(i) = min(A(i), 所有后续任务 j 的 F(j) - d(j))
S(i) = F(i) - d(i)
```

按后续节点优先的顺序计算。取 min 是为了满足每个下游，不能把并行分支耗时求和。自己的耗时影响自己的开始和上游截止，不应从自身截止重复扣除。

默认无独立约束的末端以主任务 DDL 为界。自定义日期替代本步提前约束，但不能压过更严格的依赖要求。天按 24 小时计算，分钟为存储精度；算法不处理工作日或人员资源冲突。准备开始落在过去时拒绝发布。

服务端重新计算，不能相信前端提交的最终日期。发布后不因模板修改或主任务改期而自动重排子任务；保存的预计耗时仅用于该任务建议开始时间。

## 旧客户端兼容

不同字段应选择不同策略：

| 情况 | 处理原则 |
| --- | --- |
| 旧任务没有新增可选字段 | 以兼容默认值读取 |
| 旧编辑器没传可安全保留的字段 | 保留原值，如时段和默认时长 |
| 旧编辑器可能丢失角色或依赖结构 | 返回冲突，要求刷新 |
| 用户明确移除关系 | 处理移除并清理引用 |
| 旧表单遇到新版本 | 拒绝覆盖，保留草稿供整理 |

不要统一用“缺字段就清空”，也不要无条件合并造成无法删除。

## 权限与账号边界

后台层级为成员、部门管理或网页维护管理、总管理员、创始人；两种专门管理员同级互不管理。检查实际角色、目标范围、成员版本、账号版本和必要的操作者密码。部门、网页、总管理员能力不同，不能只看一个 `isAdmin` 就放开所有字段。

公开成员列表对其他管理员投影为通用 `admin`；本人保留界面需要的实际类型。前端隐藏标签不能替代服务端授权。日历 DDL 显示范围也不应被文档夸大成数据库级的所有业务数据隔离。

多社团账号禁止被某个社团管理员代改全站身份或删除；本人自助设置仍可用。重设链接保存摘要、过期时间和授权来源，在身份与权限变化后撤销。删除账号保留历史关联与必要删除标记，同名注册生成新身份。
