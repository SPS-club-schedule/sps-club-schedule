# 进行中的尝试与接续清单

此页记录 2026 年 11 月 4 日 19:12 北京时间的并行工作状态，用于接手时区分已有成果与剩余事项。它不授权自动部署其他正在开发的功能，继续前先核对对应源码与最新交付记录。

## Android WebView 入口

已有本地 `android/` 工程、README、VERIFICATION 和 release 交付目录。1.0 保存有效会话；1.1 增加可选加密账号密码及自动重新登录；1.2 在普通登录表单默认勾选记住密码，登录成功后保存。1.2.0 的 versionCode 为 3，已验证沿用签名覆盖安装。

本地包括启动、断网、返回、文件选择、文本导出和会话桥，业务页面仍从正式站点加载。会话与密码分别用 AES-GCM 和 Android Keystore 加密；密码不回注网页，原生重新认证只访问固定 HTTPS 登录地址，失败与限流有退避。

关键接缝是网页 `sessionStorage['sps-web-session']` 及 `sps-web-club:<userId>`。网站若改变会话格式或存储键，需同步检查原生适配器。消息桥限制精确源、路径与顶层框架，iframe、外站和附件不获得原生凭据。

### 已有验证和剩余检查

本地记录包含网页登录桥专项、原生 URL、真实 WebView/Keystore 测试、release lint 和签名验证；凭据测试使用断网模拟器与伪响应，没有拿测试密码请求生产。实体手机、真实成员登录及厂商文件选择器仍需持有人实际确认。

构建按当前 `android/README.md` 核对 JDK、SDK、Gradle 版本。签名配置与私钥保存在仓库外或被忽略位置；缺少签名的 unsigned APK 不能作为正式升级包。维护时保留原签名并递增 versionCode。

此次经验归档不包含 APK、私钥、签名配置或整个源码 ZIP。若后续要分发，单独核对签名、哈希、版本及安装说明。

## Resend 邮件通知

用户已选择 Resend，发信域名为 `sps-schedule.folderrewind.top`，区域为东京。已有分别面向域名管理员和其 agent 的两份本地 DNS 说明；本次记录中域名待验证，专用发信密钥与网站通知功能尚未完成。

当时控制台给出的记录为一条 DKIM TXT 与两条 CNAME。此页不复制 DKIM 值，实际执行应读取当前完整交接文档和服务商控制台，不能套用旧教程的 MX/SPF 示例。DNS 配置、Resend Verified、API 发信成功和成员通知功能是四个不同里程碑。

### 接续顺序

1. 核对域名管理员回执与公开解析，确认只处理指定记录且现有 API 域名仍可用。
2. 在发信账号确认域名验证，再配置仅用于对应发信范围的后端密钥。
3. 设计并实现成员邮箱绑定、验证与通知偏好；当前账号恢复机制仍独立保留。
4. 明确事件规则，例如新分配、截止变更和到期提醒，处理完成或归档后的取消。
5. 建立发送记录、去重、失败重试和定时执行；外部发信不要放在数据库事务内阻塞业务。
6. 使用合适的测试地址验证退信、限流和重复执行，再按当前授权范围发布。

以上是接续方案，当前仓库没有已上线的完整通知流水线。服务价格、套餐和 DNS 要求会变化，实际实施时查官方当前说明及账号状态，不沿用旧调研数字。也不能把通知发件地址当作可收信邮箱。

## 外部主讲人与非核心角色

这是归档时新增且仍在开发的需求，工作区已出现权限、部门分类和 guest assignments 的修改。当前正式基线尚不包含完整功能。

需求分两种情况：注册的主讲人权限低于普通成员，只看并完成自己分配的任务，不能创建或删除任务；模板中的非核心角色允许在套用时自由填写未注册主讲人的姓名，由成员代标完成，并显示实际代完成人。

接续时首先区分账号角色与模板角色，避免仅通过前端隐藏入口实现受限访问。需要核对任务读取、创建修改删除、成员信息、模板、档案和导出等全部相关接口的权限；免注册姓名不能伪造为正式账号 ID，代完成需保留操作者及目标。具体实现、语义与上线结果应待该项开发完成后补录。
