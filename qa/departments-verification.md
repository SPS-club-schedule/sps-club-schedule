# 部门与部门邀请验证

日期：2026-10-30。

- 60 项 JS 测试、21 项实际 workerd/SQLite 测试、3 项网关测试全部通过；构建及 `git diff --check` 通过。
- 三个部门各有独立邀请码，服务器依据有效邀请决定部门，不接受客户端伪造的部门、角色或社团。首次初始化在事务中执行，失败回滚，并发及重试不会产生多套邀请码。
- 原通用邀请保留。旧成员默认为未分配；已加入但未分配的成员可以通过部门邀请补充分配，保留称呼、角色、成员 ID 和加入时间。重复加入不增加同步版本；已分配其他部门时拒绝覆盖。
- 创建者可以只轮换一个部门的邀请码；其他部门及通用邀请码不变，原成员归属保留。失效邀请码和越权轮换被拒绝。
- 管理员的部门修改遵循现有成员管理边界，检查同步版本，记录审计事件，并向成员同步。普通成员和跨社团修改被拒绝；旧管理客户端遗漏部门字段时不清空已有归属。SQLite 重启后部门与邀请码保持。
- 本地 Chrome 连接真实本地 Worker：验证三个部门的成员标签、选择不同部门显示不同邀请码、复制内容匹配、管理员按部门搜索、修改所属部门、保存后标签及操作记录读回。
- 使用独立普通成员会话打开宣传部邀请链接，切换到登录后邀请码保留，提交加入后显示“已加入宣传部”，成员列表显示对应归属，未出现管理入口。
- 本地轮换学术部邀请码，确认对话框指明部门，保存后显示新码。375×812 手机视口下无横向溢出；两会话浏览器日志无警告或错误。截图保存在忽略的 `qa/departments-*.png`。
- 注册、部门调整与轮换测试均使用本地或隔离测试数据；真实成员的归属不作推测。
