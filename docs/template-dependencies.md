# 模板子任务依赖

在「模板库 → 编辑 / 分类」展开一个子任务，在「依赖哪些子任务」中点击其他步骤，可以多选，再次点击取消。例如在「制作海报」中选择「撰写宣传文案」。保存后，模板列表与折叠的步骤摘要会显示「依赖：撰写宣传文案」。

使用模板时会带入依赖，发布前可以调整。发布后，任务看板、个人待办和主任务的子任务列表显示依赖链接；子任务详情显示依赖任务及其完成状态。

默认「按各步提前天数」时，依赖仅用于说明协作关系，不会自动调整截止时间。选择下述「按依赖与耗时倒排」时，依赖参与日期计算。两种方式都不会限制完成或撤销完成，宣传文案尚未完成时，海报仍可标记完成。支持同时依赖多项子任务，禁止依赖自己或形成循环。

步骤改名、排序和模板复制会保留关系；移除一个草稿步骤时，会同时移除其他步骤对它的引用。修改模板不会改变已经发布的任务。已发布的依赖任务若归档，引用处显示「已归档或不可用的子任务」；恢复后重新显示其名称和链接。

## 数据与兼容

模板步骤使用 `id` 和 `dependsOn: string[]`，引用同一模板中的稳定步骤 ID。旧模板无须迁移，编辑时生成 ID，保存时写入。服务端校验唯一 ID、引用范围和无环关系，失败时不写入部分数据。

发布时在创建主任务及子任务的同一个事务中，将步骤引用转换为实际的 `dependsOnTaskIds`。每次套用使用本次任务组的 ID，完成与日期规则不读取依赖字段。后续编辑已发布任务保留关联字段。既有的同步、归档与恢复沿用 JSON 记录，数据库位置、表和 Durable Object 绑定均不变。

不支持依赖字段的旧页面编辑或套用已有依赖的模板时会收到刷新提示，避免静默丢失关系。仍无依赖的旧模板可继续使用。部署顺序为原 API Worker、GitHub Pages 前端。

## 按依赖与耗时倒排

在模板的「子任务截止方式」选择「按依赖与耗时倒排」。每步填写「保守预计耗时（天）」，可填小数，精确到分钟；1天为24小时，包含周末，0表示里程碑。每步可选：

- **按依赖倒排**：由后续任务需要开始的时间向前推。
- **至少提前主任务**：填写提前天数，作为本步最晚完成约束；其他依赖要求更早时，采用更早的截止。

旧模板切换时保留已有提前天数作为约束，可逐步改为按依赖倒排。耗时不会猜测或自动填入，必须补全。没有后续任务且未设提前要求的步骤，以主任务截止为界。

例：文案耗时3天，海报耗时1天并依赖文案，宣传耗时1天并依赖海报，宣传至少提前研讨班1天完成。结果为：

| 子任务 | 建议最晚开始 | 截止 |
| --- | --- | --- |
| 宣传文案 | 主任务前6天 | 主任务前3天 |
| 制作海报 | 主任务前3天 | 主任务前2天 |
| 宣传 | 主任务前2天 | 主任务前1天 |

模板直接预览相对时间，套用后显示具体北京时间，并说明哪项后续任务决定了截止。主任务日期、耗时、依赖或提前约束改变时，发布前自动重算。可为本次单独指定最晚完成日期，它替代本步的提前天数约束，但不能覆盖依赖链要求的更早截止。

多条依赖可以并行，共同的前置任务采用所有后续要求中的最早截止。同一人承担的独立分支不会自动错峰，需要顺序执行时应添加依赖。若倒排结果要求在过去开始，界面会提示，发布时也会阻止提交，需调迟主任务或调整计划。

发布后保存本次具体截止和预计耗时，子任务详情显示建议最晚开始。它不是持续时段，不生成额外日历时间块。修改模板、主任务日期或完成状态不会重排已经发布的任务；单独修改已发布子任务截止时，详情中的建议开始随该任务截止更新。

### 计算与存储

令 `F(i)` 为任务最晚完成时间，`d(i)` 为保守耗时，`A(i)` 为主任务提前约束或本次指定日期；没有单独约束时 `A(i)` 等于主任务截止。若任务 `j` 依赖 `i`，则：

```
F(i) = min(A(i), 所有后续 j 的 F(j) - d(j))
S(i) = F(i) - d(i)
```

按依赖图从后往前计算。这相当于取全部下游路径中最严格的约束，不累加可并行分支的耗时；任务自身耗时影响其最晚开始及上游截止，不直接从自身截止再扣一次。

模板新增 `schedulingMode: independent | backward`，步骤新增 `estimateMinutes`（0—525600的整数或未设置的null）及 `anchorToMain`（布尔值），复用 `daysBefore` 和 `dependsOn`。未带新字段的旧模板仍采用独立提前天数。服务端重新计算全部截止后与主任务、子任务、同步版本在同一事务内保存，失败无部分写入。发布的子任务保留本次 `estimateMinutes`；依赖仍映射到实际任务 ID。已配置倒排/耗时的模板不能被不支持这些字段的旧页面静默覆盖，需刷新后编辑或套用。
