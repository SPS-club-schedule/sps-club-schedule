# 主讲人与免注册负责人

## 使用方式

“成员与主讲人”的部门 / 类别增加“主讲人”，提供独立邀请入口。通过该入口注册或加入时，服务端赋予主讲人身份。管理员也可在管理后台同时调整类别与身份；身份变更需要验证操作者密码。这个类别用于非部员主讲人，默认全选社团部员时不会选中他们。学术部、宣传部、联络部等部员也可以担任活动主讲人，直接选择其现有账号，保留原部门和账号权限。

模板角色的“负责人范围”提供两种选项：

- **仅社团部员**：套用模板时选择任意部门的部员，或按部门选人。
- **部员、主讲人或免注册姓名**：可跨部门选择现有部员、选择单独登记的主讲人，或每行填写一位免注册负责人。这些来源可以混选，一个角色可分配多人，关联步骤一起使用该名单。

免注册姓名只保存在本次发布的任务中，不创建账号，不占成员名单，也不保存到共享模板。最多填写 50 人，每个姓名最多 40 字；去除首尾空白并合并重复姓名。相同姓名在不同任务中的完成状态相互独立。已发布子任务如有完成记录，须先撤销后才能更换负责人。

## 查看与完成权限

| 身份 | 查看 | 创建与修改 | 完成 |
| --- | --- | --- | --- |
| 社团成员及管理员 | 保留原有社团任务范围 | 保留原有任务、模板权限 | 完成自己的任务；可代同社团主讲人或免注册负责人完成 |
| 已注册主讲人 | 仅分配给自己的任务和个人日程 | 不能创建、编辑、归档任务，不能操作模板或成员后台 | 只能完成自己的分工，不能代其他人完成 |
| 免注册负责人 | 无登录账号 | 无 | 由同社团已登录成员代为标记 |

“任何人代完成”指同社团的已登录核心成员，不要求其也是该任务负责人。普通核心成员的分工仍只能本人完成。主讲人可维护个人登录资料，但不能上传经验档案或读取预约同步管理信息；公开资料仍按原有公开访问规则提供。

任务详情逐人显示 `由 张三 代 李老师 标记完成` 和完成时间。“逐人完成”要求全部负责人完成；“协作完成”由其中一位负责人完成即结束，代完成同样保留实际操作者。重复请求不会覆盖先前操作者。撤销代完成仅允许实际操作者、被代完成的注册主讲人、任务发布者 / 主任务发布者或社团创建者。

部门管理员可以维护主讲人及本部门下级成员；调整类别和任免权限仍由总管理员或创建者执行。主讲人不能通过其他部门邀请码自行升级身份。

## 数据与同步

- 成员使用 `role: "speaker"`、`department: "speaker"`；两者必须对应。
- 模板角色 `coreMember: false` 表示允许部员、非部员主讲人和免注册姓名共同担任；不改变被选人的部门或账号身份。旧模板没有此字段时仍仅限部员；旧编辑器不能静默丢掉已有负责人范围设置。
- 已发布任务保留原 `participantIds`，额外使用 `guestParticipants: [{id, name}]`。免注册 ID 由服务端根据姓名生成，完成状态只在所属任务内使用。
- 逐人完成仍在 `completions[targetId]` 保存时间；代完成另在 `completionActors[targetId]` 保存 `actorId`、当时姓名 `actorName` 和 `at`。协作完成将目标保存在 `sharedCompletion.memberId`，代完成另存 `actorId`、`actorName`。
- 服务端从登录会话确定操作者，不接受客户端提供的操作者姓名或身份。客户端仅传 `participantId` 选择被代完成的负责人。
- 主讲人同步返回受限的全量任务集合，撤回分配或降级身份后会清除旧列表；恢复成员身份会重新取得历史任务。相关任务可见的协作者及操作者姓名保留，未分配任务、模板和无关成员不下发。

无需数据库迁移。部门模板教程同步说明负责人范围、跨部门主讲人、自由姓名和代完成规则；主讲人不会自动进入成员或管理员教程。

## 验证

`tests/speakers.test.js` 覆盖邀请身份、防自助升级、任务隔离、降级发布者限制、角色复制与解绑、免注册名单、代完成归属和撤销、越权与渲染转义。`tests/speakers.test.mjs` 在真实 Worker runtime / SQLite 中验证重启持久化、重试幂等、任务 / 模板 / 档案权限、服务端归属和身份升降级同步。浏览器验收使用独立本地测试账号，覆盖模板设置、混合分配、普通成员代完成、主讲人本人完成及手机视图。
