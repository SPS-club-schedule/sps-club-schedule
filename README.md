# SPS 社团日程 · 网页版

中文社团任务协作应用。GitHub Pages 托管静态网页，Cloudflare Workers 提供 API，SQLite-backed Durable Object 持久化账号、社团、任务及完成记录。不再依赖微信小程序、AppID 或腾讯云开发。

API 入口使用 Leafuke 提供的 `https://sps-schedule.folderrewind.top`，经网关访问原有数据库；配置与回滚见 [域名网关说明](docs/cloudflare-gateway.md)。

正式网站：[SPS 社团日程](https://sps-club-schedule.github.io/sps-club-schedule/)。独立仓库：[SPS-club-schedule/sps-club-schedule](https://github.com/SPS-club-schedule/sps-club-schedule)。本机独立项目目录：`/Users/grassman_number/Projects/sps-club-schedule`。

沿用原版的绿色配色、任务看板、逐人/协作完成、成员进度、截止时间、搜索和个人待办。所有社员可以发布任务；发布者与社团创建者管理任务。任务参与名单发布后固定，归档保留完成记录。

任务看板和“我的待办”包含小型任务日历：按北京时间标记未完成任务的截止日期和数量，可切换月份、回到今天、点选日期查看当天任务，或查看整月列表并直接打开任务详情。逾期任务以暖色标记，逾期数量可跳转到最早的逾期日期。社团日历保留尚未全部完成的逐人任务；个人日历仅显示自己还需完成的任务。完成、撤销完成、修改截止时间及归档后，日历随任务同步更新。下方任务列表的搜索和分类不影响日历。

主任务默认“仅截止时间”，也可选择“有持续时段”，填写开始/结束日期与时间（北京时间）。启用时预填一小时，可自行修改；截止时间默认跟随开始时间。直接修改截止日期或时间后，切换为手动设置并保存该选择；之后改变时段不会覆盖截止时间，也可点击“恢复跟随开始时间”。已发布任务仍可按原有权限编辑时段，关闭时段会保留当前截止时间。子任务仅设置和显示截止时间。

“任务日历”在持续时段覆盖的每天显示蓝色短线，列表显示完整起止时间和独立截止时间，支持跨日、跨月；结束时刻为午夜时不占用下一天。同一任务在同一天和整月列表中各计一次，手动移到时段外的截止日期仍有标记。日历继续遵循现有未完成任务/个人待办筛选。时段采用可选 `startsAt`、`endsAt`、`deadlineFollowsStart` 字段，旧任务无需迁移；旧客户端未传时段字段的编辑保留原时段。

任务详情中的“＋ 添加子任务”可为主任务拆分分工，每个子任务单独选择负责人、截止时间和完成方式。主任务发布者与社团创建者可以分配和管理子任务；成员在“我的待办”及截止日历中看到分给自己的未完成事项。已有完成记录的子任务须先撤销完成再更换负责人。主任务和子任务分别标记完成；归档主任务会一并归档子任务并保留全部完成记录。当前支持一级子任务。

任务、子任务和模板的负责人区域支持“按部门选择”：点击宣传部、联络部或学术部，替换为该部门全体成员；再点击姓名可转为手动调整。模板会保存部门规则，每次使用和发布时按最新部门名单分配。没有成员的部门可以在模板中预设，但不能发布空名单任务。发布后的名单固定，新成员或部门变动不会自动改写旧任务和完成记录。

底部“模板库”在本社团内共享，所有成员都可以创建、复制、编辑和分类，按分类或关键词查找。内置“研讨班 Seminar”：预约教室提前4天，制作海报与撰写宣传文案提前3天，向各院系群转发宣传提前2天，完成 PPT 或讲义提前1天。模板支持1—20项子任务、各自的默认负责人、完成方式与优先级；提前天数为0—365天。模板创建者或社团创建者可以归档模板。

模板可在“主任务默认时间”选择“默认持续时长”，用小时和分钟保存，例如2小时30分钟。模板列表显示该时长；编辑、复制和同步都会保留。套用后自动开启主任务持续时段，选择或修改开始时间时自动计算结束时间，支持跨天、跨月、跨年。手动修改结束时间后停止自动覆盖，可点击“恢复按模板时长计算”；手动截止时间独立保留。无时长模板默认使用截止任务。发布后存储本次具体起止时间，后续修改模板不会改动已发布任务，子任务不使用默认时长。服务端新增可选 `durationMinutes`（正整数分钟，`null` 表示不设置），旧模板无需迁移，旧客户端未传该字段的编辑会保留原值。

在模板库点击“使用模板”，或在发布页选择模板并“套用”，设置主任务截止时间后，子任务自动保留相同的北京时间并向前推算。发布前可修改每一步、负责人、顺序和提前天数，也可单独指定日期；之后调整主任务日期时，仅按提前天数计算的步骤会更新。每项任务都须分配负责人，已过期或晚于主任务的子任务日期会阻止发布。主任务与全部子任务在一个事务内创建，重试不会重复创建。模板中的默认负责人可留空，使用时再分配；主任务未设默认参与成员时预选当时的全体成员。模板修改以及发布后修改主任务的截止日期，都不会自动改写已发布的子任务。

模板子任务和发布前的步骤可以设置“跟随主任务负责人”，自动采用主任务当前选中的全部成员，随主任务分工同步更新；切回“单独指定”时保留当前名单。“全部交给我”会取消各步骤的跟随/部门规则，明确指定给操作者。服务端在同一事务中解析主任务和子任务名单。模板新增的 `participantDepartment`、步骤 `followMain` 为可选字段，旧模板保持原行为，无需数据库迁移；已发布任务只存最终成员 ID。

## 与物院社团预约互通及个人导出

任务日历显示其他社团的活动名称、社团、持续时段和地点（不含课程），可直接打开预约总览。有持续时段的 SPS 主任务自动同步为预约页上的 SPS 活动；可选填地点，未填显示“未定”。修改时间、地点、归档、恢复会自动更新，后台失败会重试；同步块从原任务管理。原手动预约和课程保留。

每位成员可点击日历中的“导出我的日程 .ics”，导出自己负责的未结束活动与未完成截止事项，供导入个人日历；文件是当前快照，变化后需重新导出。详见[使用规则、连接与验证](docs/booking-integration.md)。

## 使用

第一次使用：选择“注册并加入”。已有社团成员填写邀请码；社团负责人选择“创建社团”。用户名使用3—30位英文字母、数字或下划线，密码至少10个字符。社团称呼可用中文。保存仅显示一次的账号恢复码，然后开始使用。

只有社团创建者和管理员可以在成员页查看、复制邀请码或分享邀请链接，通用邀请码和三个部门邀请码均适用。普通成员只显示“邀请新成员请联系本社团管理员”，服务器拒绝其直接获取邀请码的请求。管理员被撤销权限后，下一次同步会清空页面中的邀请码及缓存。新用户通过管理员发来的邀请注册；已登录用户通过邀请加入。创建者更换某个邀请码会使对应旧链接失效，不影响已有成员。已经发出的邀请码仍可在站外被转发；此权限限制不会自动作废旧邀请。登录会话仅保存在当前浏览器标签页的 `sessionStorage`，关闭标签页后需要重新登录；服务端会话最长7天。退出登录会立即撤销当前会话，密码恢复会撤销所有旧会话并更换恢复码。

成员页的“邀请加入部门”提供宣传部、联络部、学术部三个独立邀请码及邀请链接。使用对应入口注册或加入时，由服务器自动设置所属部门；每位成员当前归属一个部门。已有但未分配部门的成员也可使用部门邀请补充分配，重复加入保留原称呼、角色和加入时间；已属于其他部门时会提示联系管理员调整。原有通用邀请码继续有效，仅加入社团，不分配或清空部门。创建者可以单独更换某个部门或通用邀请码，其他入口与现有成员不受影响。

成员列表和管理后台显示每个人的所属部门；已有成员默认显示“未分配”，不会推测其归属。后台支持按部门名称搜索，并可在“编辑资料 → 所属部门”中分配、调换或清空部门。部门资料遵循原有成员管理权限，修改会同步到成员列表并记入管理记录；仅改称呼或部门不需要输入密码。

忘记密码时，在登录页选择“用恢复码找回”。不依赖邮件服务。若同时丢失密码和恢复码，可联系本社团管理员生成一次性密码重设链接。

每位成员都可从“社团成员 → 账号设置”修改自己的登录用户名和密码；“切换、加入或创建社团”页也提供入口，无需管理员权限。两项修改分别提交，均需验证当前密码；用户名须为3—30位英文字母、数字或下划线，不区分大小写且全站唯一；新密码须为10—128个字符，不能与当前密码相同。所有社团共用同一登录账号，修改不会改变社团称呼、部门、角色或任务记录。

修改用户名后旧用户名失效，现有登录和恢复码仍然有效，待使用的密码重设链接失效。修改密码后当前会话保持登录，其他会话全部撤销；旧密码、旧恢复码，以及此账号接收/签发的重设链接失效。新的恢复码仅在成功页面显示一次，须重新保存。自助修改和管理后台共用账号版本检查：若账号已被其他页面或管理员修改，先点击“重新加载账号资料”再操作，避免旧表单覆盖更新。服务端仅按当前会话确定操作对象，不接受客户端指定其他人的账号；密码验证失败按账号限流，事务失败不会绕过限流。

## 管理后台

社团创建者自动拥有管理权限，底部可见“管理后台”。创建者可以任免管理员；管理员可查看本社团成员的称呼、角色、登录用户名及加入/注册日期，修改普通成员资料，也可维护自己的资料。其他管理员和创建者由创建者管理，创建者身份不可降级或转让。普通成员看不到入口；直接打开管理网址或伪造 API 请求也会被拒绝。任务和模板原有的编辑权限保持不变。

可修改社团称呼、角色、登录用户名。修改用户名、任免管理员、生成密码重设链接需要输入操作者自己的密码。保存采用成员同步版本和账号版本检查，过期表单不会覆盖别人的修改。账号用户名在该账号下的会话中随下一次同步更新。账号若已加入其他社团，社团管理员只能维护本社团资料，不能替其他人修改其全站登录用户名或生成密码重设链接；账号本人始终可以通过“账号设置”维护自己的登录资料。

密码不会显示给管理员。管理员生成的重设链接仅在内存中显示一次，有效期30分钟；重新生成使之前的链接失效。成员打开链接并设置新密码后，全部旧会话和旧恢复码失效，新恢复码只向成员本人显示。签发管理员被撤销权限、目标角色变更、账号用户名变更、恢复码找回，以及目标加入其他社团，都会使相应重设链接失效。链接发放本身不会改密码或退出成员登录；需成员本人完成重设。

“管理后台 → 编辑资料 → 删除成员账号”允许管理员删除普通成员的网页账号，创建者也可以删除管理员账号；不能删除自己或社团创建者。账号已加入其他社团时禁止删除，避免本社团权限影响其他社团。删除需输入操作者自己的密码并在显示成员称呼及用户名的对话框中确认；服务器重新检查权限、成员版本及账号版本，过期表单须重新打开。

删除不能撤销：账号、密码和恢复码被移除，所有登录会话以及该账号接收/签发的重设链接立即失效。历史任务、模板、分工及完成记录保留，任务中的历史姓名显示为“已离开的成员”；未完成分工不会自动算作完成，可由有权限的人归档旧任务并重新安排。成员列表与新任务的选择名单同步移除该成员；旧版已打开页面以全量同步更新。服务端仅保留不含姓名、登录身份及角色的成员删除标记以支持同步和历史关联。同名重新注册生成新身份，不继承旧分工或完成记录；本功能不封禁再次注册。

后台显示最近30条资料修改、重设链接签发及账号删除记录，记录操作人、目标成员、变更字段与北京时间，不记录密码、恢复码或重设令牌。已删除成员显示为“已删除成员”。角色撤销立即影响服务器授权；已打开页面在下次同步时清空管理资料和入口。

管理后台提供独立的“归档恢复 →”入口，默认管理页不展开归档列表。进入后分“任务 / 模板”查看、搜索和预览已归档内容；只有本社团创建者和管理员可恢复，普通成员即使是原发布者也不能自行恢复。恢复前显示内容名称与影响，恢复后重新出现在任务看板或模板库，沿用原编辑权限。

恢复主任务会同时恢复当时随主任务一起归档的子任务；此前单独归档的子任务仍保留在归档区，主任务恢复后可再单独恢复。主任务尚未恢复时禁止单独恢复子任务，缺失主任务的子任务也不能恢复。任务原负责人、完成记录、截止时间和持续时段均保留；逾期任务仍按原截止时间显示。模板保留原步骤、部门/负责人规则和默认时长，不改变已发布的任务。恢复检查当前版本并与社团同步版本在同一事务内提交，重复请求或旧页面不能误恢复后来重新归档的内容；已有归档数据可以直接使用，无需迁移。

## 本地运行

需要 Node.js 22 或更新版本。

```sh
npm ci
cp .dev.vars.example .dev.vars
npm run worker:dev
```

另一个终端：

```sh
npm run build
npm run preview
```

网页位于 `http://127.0.0.1:4175`，本地 Worker 位于 `http://127.0.0.1:8787`。本地数据保存在忽略的 `.wrangler/` 内，和正式环境完全分开。前端所有请求实际经过本地 Cloudflare runtime 与 SQLite，不是内存演示。旧微信演示数据不会自动上传。

## 同步

前台15→30→60秒自适应检查；只传回有变化的任务、成员和归档标记。自己的操作在服务器确认后直接更新。切到后台或离线停止自动请求，回到前台、恢复联网和手动刷新立即检查。读错误保留上次确认内容，最多退避120秒；身份失效清空缓存并回到登录页。编辑草稿不被定时读取覆盖。

身份来自服务端会话，不接受客户端伪造的成员标识。共享领域逻辑在 SQLite 事务里写入任务和社团版本号；Durable Object 串行处理异步领域操作，避免同时打勾丢失数据。当前面向小型社团部署，使用单个 Durable Object 保存所有社团，各社团仍逐请求验证成员权限；大规模多租户服务需进一步拆分和分页。

## 结构

- `client/`：原生 HTML/CSS/JavaScript 网页，没有微信运行时或框架依赖。
- `shared/`：任务规则、时间格式、增量同步调度器。
- `server/`：Cloudflare Worker、SQLite 适配器、账号与会话。
- `scripts/`：静态站点构建与本地预览。
- `.github/workflows/pages.yml`：测试、构建和部署 GitHub Pages。
- `qa/verification.md`：本次验证范围。

部署说明：[GitHub Pages 与 Cloudflare 接入](docs/deployment.md)。本项目已从原 AI 工作区移出，部署工作流只操作这个独立仓库。
